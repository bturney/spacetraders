## Updating a row

When a capability spec is approved **in a GitHub issue**, link that issue in the relevant row and mark *planned*, not implemented. Link finite implementation tickets to the spec issue according to [issue-tracker conventions](../agents/issue-tracker.md). On merge, link source/PR and record *implemented*. On validation, link the exact pinned scenario, baseline, attempt/results and limitations, and upgrade only the covered *proof*; distinguish local deterministic tests, simulator-conditional comparisons and live operational qualification. Mark **superseded** with the replacing decision rather than pretending an old contract passed.

See [change process](change-process.md) for how updates are made, and [roadmap](roadmap.md) for priority. The old issue's five gates and C01–C12 remained historical framing; this ledger summarizes their **remaining outcome obligations** after #502 closes. It is not a second detailed specification or ticket tracker.
