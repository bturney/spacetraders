## The five Operator questions

Classes: **presentation** = retained/projected fact not meaningfully shown; **projection** = missing bounded read/join; **retained evidence/instrumentation** = necessary fact/history not established; **model/qualification** = behavior or proof not established; **unverified** = inaccessible or untested, never proof of absence.

## Deeper outcome → evidence → Grafana → return

The [router][router] has Mission Control, Operations, Ship/Waypoint/Contract/Construction, Activity, Generations and Episode destinations, but **no routed Objective or Endeavor detail**. Operations has local Endeavor anchors. The recoverable current path is Operations → Ship or Episode; Activity/Generations → Episode → contextual Grafana. The Episode breadcrumb returns only to Generations, not originating work; Ship has no reverse purpose/Episode link; Mission Control notable entries have no individual evidence link. [Entity pages][entity] preserve explicit historical Generation scope and observed facts; Market/Shipyard remain Waypoint contexts. This is a **navigation/projection gap**, not authorization to redesign Atlas or introduce another top-level product.

Five necessary owner-held correction groups (candidate specification inputs, **not implementation decisions**):

1. **Show retained reasons and causal identity.** Reuse Episode alternatives/constraints, kind/reason, original Portfolio Episode plus Commitment replan Episode, and existing entity paths. Expose observation identity/time and inspectable unknown-cost entries rather than raw-ID transcription. Owner: MissionControl/LiveViews. **Cost:** small read projection/template changes and navigation proof; simplest alternative is existing Episode links, but those alone do not currently supply missing kind/next-stage explanations. No new permanent table or generic explanation framework is justified.
2. **Retain original versus later decision evidence.** [NeutralWait refresh][wait-refresh] overwrites `expectations`, `evidence_references`, `alternatives`, and `calibration_version`; [re-evaluations][wait-history] retain timestamps/subjects/demand IDs, not those original snapshots. The Episode page nevertheless says references were retained “when this episode was selected.” **Retained-evidence defect:** preserve initial provenance/expectations while retaining distinguishable later material evidence in the existing Episode owner. Labeling “latest” is a truthful immediate alternative, **not a complete solution to original-versus-new reasoning**; old erased facts cannot be reconstructed honestly. **Cost:** explicit original/latest retention and bounded material-history policy/qualification, not a second event store; exact storage design remains undecided.
3. **Make current work, next boundary and capital coherent.** Compose existing Commitment/Intent/Observation facts, Reservations, CreditSpending authority and Shortfalls at an explicit time boundary; protect balance/floor/reserved/admitted/in-flight/Bounded Unknown distinctions ([ADR 0013][adr13]). Do not compute “available” by subtracting unrelated dashboard counters or double-count Reservations and execution exposure. Owner: MissionControl read projection over Allocation/Execution/CreditSpending. **Cost:** bounded joins and freshness/unknown tests. Existing reservations and release predicates are simpler than a new capital ledger, but do not yet constitute the complete headroom answer.
4. **Keep economics/history comparable, not merely adjacent.** [TradeProgress][trade] separates completed-trip Trade Margin, own-root supporting charges, Net Earnings, Episode Cash Flow and coverage spending, names missing attempt/Commitment evidence, and never substitutes balance delta. [Current projection][economics] carries much more of this than the summary renders. [Planning][planning] explicitly lists fuel/travel time as unaccounted costs in ordinary Market expectations: projected value is not a complete Net Earnings forecast. [Generation recaps][recaps] sum numeric credit-change fields only from realized Episodes with references; this is not proven complete Generation balance change or a normalized cohort. Historical objective validity also applies a present-time 300-second age check to retired Generations ([source][mc-objectives]); valid old evidence can therefore become unknown. Owner: MissionControl with source owners for missing facts. **Cost:** scoped units/window/completeness/sample-size projection and historical-validity correction. Simpler alternative: show dated retained episode facts side by side with explicit incomparability; leave rates unknown until denominators/attribution are established. Multi-Ship producer–hauler profit, Strategy-capable rates, and forecast accuracy remain **model/qualification or missing-evidence questions**, not results supplied by these charts; no planner expansion is authorized here.
5. **Repair the diagnostic handoff, reuse Outcomes first.** [GrafanaLink][grafana-link] accepts Generation/Revision/Episode/Commitment/Intent/Attempt and UTC time, without credentials. Actual Episode callers pass only Generation/Revision/Episode; deeper causal IDs are not magically scoped. All five deployed families use the same log query and unscoped metric trends. **Proven filter mismatch:** Allocation logs emit `active_revision_id`, `portfolio_revision_id`, `commitment_ids`, whereas dashboards filter `strategy_revision_id`, singular `commitment_id`. Owner: Allocation logging plus dashboard provisioning, with explicit active-versus-original Revision semantics. **Cost:** align that small contract and prove populated and empty cases, preserving bounded metrics and JSON-only high-cardinality IDs. Simpler diagnostic fallback: Generation+Episode+time query, which genuinely worked below; dropping all filters is not a complete causal handoff. Reuse/link existing Outcomes panels before adding metrics. New recovery-duration, normalized outcome or information-usefulness signals require a demonstrated missing source, denominator and retention rule; no generic telemetry platform.

## Resolution boundary and walkthrough handoff

The factual inventory is resolved **within the recorded source/query boundary**. Essential answers cannot be deferred as “only polish”: original evidence retention, causal filter alignment, current-work/next-boundary joins, scope/completeness and historical validity require explicit owners in the eventual bounded specification. Conversely, populated telemetry does not qualify broader autonomous behavior or choose the interaction design.

**Remaining access/validation:** an Operator-authenticated app session and real desktop/phone walkthrough, plus rendered Grafana with the actual contextual link/time/identity. No credentials need to be given to an agent. The HITL walkthrough must measure the five answers within 60 seconds, follow work → Ship/Waypoint → why/outcome/evidence → Grafana → return, inspect unknown/stale/state distinctions and live-update stability, and record the Operator's actual comprehension and enjoyment. Reuse genuine retained examples; no new live trial or mutation is implied. No HITL ticket is resolved by this note.
